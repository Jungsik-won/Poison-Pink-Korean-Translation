# 상단 행동 제목·공통 선택지 시험본

후속 최신 빌드와 현재 재현 지점은 [스킬 분류·상태·명령 통합본](UI_REMAINING.md)을 따른다. 아래는 제목 v2 단계 기록이다.

2026-09-15. 전투 메뉴 이미지와 별도로 남아 있던 ELF 문자열을 고정 길이로 번역한다.

## 산출물과 범위

- ISO: `build/ui_titles_v2/Poison Pink (Japan) - UI titles.iso`
- SHA-256: `aa1f65d793a00a97310e94ac03ef3b796f7379d107973e5927a8ad5b8fcfeca6`
- 바탕: UI v3 `0612fc3ac65db987bd5772898b3288e6cc07028543d4be131f1c15af0d824e78`.
- 문자열 15곳: 행동 제목 9종, `はい→예` 2곳, `は　い→예` 2곳, `いいえ→아니요` 2곳.
- 폰트 6자 추가: 령·열·예·요·태·획. 총 2,202글리프, 기존 2,196개 바이트 보존.
- 전체 ISO 변경 519바이트. SYSTEM 내부 빈 패딩만 사용하며 모든 ISO 파일 위치·크기, 다른 자산은 보존한다.
- ELF 변경으로 PCSX2 CRC는 **F76412F3**이다. 과거 빌드의 F7786EE4 상태 파일을 섞어 검증하지 않는다.
- 첫 제목 시험본과 보완본은 CRC가 같다. CRC만으로 빌드를 구별할 수 없으므로 ISO SHA-256과 실행 경로를 함께 기록한다.
- 번역 입력: [ui_titles.json](../localization/ui_titles.json), 정적 결과: [ui_titles.json](../reports/ui_titles.json).

## 문자열 참조와 길이 제한

`tools/ui_titles.py`는 원본 ELF SHA, ELF32/MIPS LOAD, `.sdata` 구간, 독립 NUL 문자열과
정렬된 포인터 참조 전체를 확인한다. 번역된 바이트는 원문보다 길어질 수 없고, 남은 공간은
NUL로 채운다. 주소·포인터·명령어·할당 용량은 바꾸지 않는다.

| 원문 | 번역 | 원문→번역 바이트 | ELF 파일 오프셋 |
| --- | --- | --- | --- |
| 移動 | 이동 | 4→4 | 0x453468 |
| 攻撃 | 공격 | 4→4 | 0x453470 |
| スキル | 스킬 | 6→4 | 0x453478 |
| 命令 | 명령 | 4→4 | 0x453480 |
| 開ける | 열기 | 6→4 | 0x453488 |
| 捕獲 | 포획 | 4→4 | 0x453490 |
| 道具 | 도구 | 4→4 | 0x4534a0 |
| 状態 | 상태 | 4→4 | 0x4534a8 |
| 待機 | 대기 | 4→4 | 0x4534b0 |
| はい | 예 | 4→2 | 0x452808, 0x453618 |
| は　い | 예 | 6→2 | 0x452820, 0x453368 |
| いいえ | 아니요 | 6→6 | 0x452810, 0x453370 |

첫 시험본은 공백 없는 `はい`만 번역해 출격 확인창의 예가 일본어로 남았다.
전각 공백 변형 두 곳을 추가했다. `0x452820`은 포인터 표 없이 `0x10b934`의
LUI/addiu 명령에서 주소를 만들므로 이 세 명령어도 원시 값으로 고정해 검증한다.
첫 시험본과 검수 입력은 `build/ui_titles/`에 보존했다.

직접 참조 예: 파일 `0x4a124`~`0x4a130`에서 이동 문자열의 포인터 표를 읽어
`0x1462d8` 호출의 `a1`에 전달한다. 파일 `0x10a7bc`에서는 `gp-16216`에 있는
예/아니요 표를 `0x20ad48` 호출에 전달한다. 모든 소비자의 호출 그래프를 해석한 것은 아니다.
[원시 명령어·포인터 목록](../reports/ui_titles_elf_audit.json)을 보존했다.

## 스킬 분류 그림: 주입 보류

`sys011`의 액티브 스킬·마법 스킬·마신 소환은 원본을 유지한다. 원본은 반투명 픽셀을
사용하므로 기존 불투명 RGB 가져오기를 적용하면 안 된다.

`ui_slice.py`에 명시적인 `rgba_palette` 모드를 추가했다. 실제 알파 채널이 없는 이미지를
거부하고, 미리 곱한 RGB와 알파를 함께 비교해 원본 팔레트 인덱스로 변환한다.
원시 GS 팔레트·헤더와 승인 사각형 밖 픽셀은 그대로 유지한다. 합성 입력 테스트는 통과했지만
이 모드의 실제 게임 자산 주입·실행 검증은 아직 없다.

built-in image_gen으로 만든 시안 두 개는 각각 노란 테두리 추가, RGB 체크무늬 배경 때문에
제외했다. [시안과 프롬프트 기록](../localization/ui_titles_image_prompts.json)에 보존했으며,
이 그림들을 최종 게임 자산으로 사용하지 않는다. 다음 단계는 실제 RGBA 시안 검수부터 시작한다.

## 재현

```sh
python3 tools/ui_titles.py --output-dir build/ui_titles_next --prepare-only
python3 tools/ui_titles.py --output-dir build/ui_titles_next
PYTHONPATH=tools python3 -m unittest test_ui_titles test_ui_slice
```

관련 전체 테스트 52개 통과. 길이 초과·포인터 변경·미검수·겹침·원본 변경, 알파 누락과
팔레트 보존을 검사한다. 새 ISO는 별도 폴더에만 생성하며 완료된 빌드는 덮어쓰지 않는다.

## 실행 검증

실행 근거: [ui_titles_runtime.json](../reports/ui_titles_runtime.json). 정적 보고서의
`runtime_verified=false`는 빌드 시점 값으로 유지한다.

- 최종 v2를 상태 파일 없이 새 부팅해 No.02를 로드하고 본편 전투에 진입했다.
- 출격 확인창의 예/아니요 일반·강조 표시, 아니요 취소와 예 전투 진입을 확인했다.
- 재행동 취소 확인창에서도 예/아니요를 확인했다. 이 창의 양쪽 분기는 실행하지 않았다.
- 상단 제목 **이동·공격·스킬·도구·대기** 5종을 확인했다. 공격·스킬·도구는 대상 선택 단계다.
- 명령 하위 화면의 제목은 개별 명령명 `再行動`이다. 상태 화면의 `状態`는 이미지 제목이다.
  공통 ELF 명령·열기·포획·상태의 표시와 새 글리프 6자 전부의 출력은 확인했다고 주장하지 않는다.
- 기존 한글 마법·아이템 이름과 설명, 메뉴, 상태 화면 진입, 대기 후 다음 유닛 진행을 확인했다.
- 같은 ISO의 명령 대상 선택 상태를 저장했다. 취소 확인창을 연 뒤 복원하여 창이 사라지고
  저장 지점으로 돌아오는 것을 확인했다. F3 호출은 두 번이며 뚜렷한 화면 전환 검증은 한 번이다.
- 상태 파일: `build/ui_titles_v2/evidence/order-target.p2s` (8,570,260B).
- 이 단계의 PID 62705는 후속 검증을 위해 종료했다. 현재 PID·상태는 [UI_REMAINING](UI_REMAINING.md)을 따른다.
- 진행 카드 두 개의 SHA-256은 작업 전후 동일하다. 게임 내 저장을 덮어쓰지 않았다.
- Software·MTVU 설정을 사용했다. 광범위한 상태 호환성·폰트 용량·P4 완료 검증은 아니다.

### 캡처 시 주의할 재현 조건

이 설정에서는 일시정지 중 F8 요청이 즉시 파일로 나오지 않고 재개 후 처리되는 경우가 있었다.
`titles-v2-state-saved` 캡처는 실패했고, 다음 요청이 앞선 지연 이미지를 집은
`titles-v2-before-restore.png`는 근거에서 제외했다. 남은 요청을 처리한 뒤 실행 중에
새로 캡처했으며, 최종 정지는 F8 없이 수행했다. 캡처 파일이 생겼다는 사실만으로 입력 직후
화면이라고 단정하지 않는다. Python 3.8 zipfile은 이 상태 파일의 압축 방식을 지원하지 않아
ZIP 전체 검사로 통과 처리하지 않았으며, 실제 PCSX2 복원 로그와 화면을 근거로 삼았다.
