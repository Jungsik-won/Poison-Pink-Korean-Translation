# 한글 글리프 실제 실행 검증

2026-09-15. **실험 ISO를 새로 부팅한 게임 대화창에서 `가나다` 출력 확인.**

최신 후속 결과: [일본어 보존 + 한글 한 문장 검증](KOREAN_SENTENCE_PROBE.md)에서 32자 추가와 실제 번역문 출력을 확인했다. 아래 표는 최초 세 글리프 진단 실험의 기록이다.

## 환경

- PCSX2 v2.6.3, Metal, 게임의 NTSC 640×448 모드.
- BIOS: Japan v02.00 (14/06/2004), 사용자가 제공한 SCPH-70000 파일의 로컬 사본.
- 게임: SLPS-25854, CRC F7786EE4.
- 설정/BIOS/메모리카드/캐시/상태 파일 모두 `build/runtime`의 시험용 사본 사용.
- 기존 사용자 PCSX2 설정과 메모리카드는 변경하지 않았다.
- 프로세스 실행·화면 입력은 macOS 접근이 필요해 샌드박스 밖에서 수행했다.
- 최초 문자 키 매핑에서 게임 입력이 인식되지 않아 Start/Circle/Cross를 F10/F11/F12로 바꿨다.
- 캡처는 PCSX2 자체 F8 스크린샷 기능이다. 비교 이미지는 각각 새로 부팅해서 얻었다.

설정 초기화와 CLI 옵션은 설치된 실행 파일의 `-help` 및 [PCSX2 v2.6.3 QtHost 소스](https://github.com/PCSX2/pcsx2/blob/v2.6.3/pcsx2-qt/QtHost.cpp)를 참고했다.

## 재현 방법

프로젝트 루트에서 다음 명령으로 최초 폰트 진단 실험본을 새로 부팅한다. 현재 열려 있는 앱은 후속 한 문장 실험본이다.
이미 실행 중이면 해당 세션을 종료한 뒤 실행한다.

```sh
'build/runtime/PCSX2-v2.6.3.app/Contents/MacOS/PCSX2' \
  -portable -nogui -fastboot -nofullscreen \
  -logfile "$PWD/build/runtime/manual-probe.log" \
  -- "$PWD/build/font_probe/Poison Pink (Japan) - font-probe.iso"
```

1. 타이틀에서 F10(Start).
2. `prologue`에서 F11(Circle).
3. 영상이 시작되면 F10으로 건너뛴다.
4. `ラキ: 戦い方の基本を教えるぞ` 대사까지 기다린다.
5. F11 → 설명 여부 선택지에서 오른쪽 → F11로 `いいえ` 선택.
6. 다음 라키 대사를 F11로 진행한다.
7. 이름창의 `가나다`를 확인하고 F8로 캡처한다.

`tools/runtime_keys.py --pid <시험용 PID> start/circle/right/screenshot`으로도 입력할 수 있다.
이 도구는 프로세스 실행 파일 경로가 프로젝트의 시험용 PCSX2와 일치하는지 확인한 뒤 입력을 보낸다.

## 상태 저장 검증의 제한

`build/runtime/evidence/korean-dialogue.p2s`의 내장 썸네일에는 기대한 한글 대화창이 있다.
그러나 이 상태를 로드하고 재개한 후의 새 캡처에는 대화창이 사라졌다. 원인을 확정하지 않았다.
로그에는 일반적인 MTVU 상태 저장 안정성 경고가 있으나, 이번 현상의 원인이라고 단정하지 않는다.
이 상태 파일은 조사 자료로 보관하고, 검증된 재현 방법은 위의 새 부팅 절차로 한정한다.
폰트 기능과 독립적으로 원본 상태 복원 비교, MTVU off 대조, 게임 내 저장/로드를 추가해야 한다.

## 당시 후속 작업 목록

아래 1번과 3번의 동일 길이 한 문장 실험은 후속 작업에서 완료했다. 전체 파서와 광범위한 용량 검증은 남아 있다.

1. 사용하지 않는 유효 코드 슬롯을 선별하고 기존 일본어를 보존하는 32~64자 한글 집합을 만든다.
2. 폰트 크기 확대, ID/힙/캐시 상한, 다양한 계조·겹받침을 검증한다.
3. RTB 명령 파서/원문 왕복과 같은 길이 한 문장 재삽입을 구현한다.
4. 증가·감소 길이와 분기 검증을 통과한 뒤 20~30문장 실제 번역 구간으로 확대한다.
