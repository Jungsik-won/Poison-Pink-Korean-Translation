# 타이틀 흰색 투명도 선택 오류 수정

## 발견

사용자가 게임에서 흰색 글자에 배경이 비쳐 보인다고 보고했다. 타이틀 팔레트에는 RGB가 모두 (255,255,255)이지만 저장 알파가 140·164·230·255인 서로 다른 항목이 있다. 원본 일본어 타이틀 첫 줄의 불투명 흰색은 인덱스 255 / 저장 알파 255를 사용한다.

기존 변환기는 검사 PNG용 `min(alpha*2,255)`를 색상 비교에도 사용했다. 이 과정에서 네 흰색의 알파 차이가 사라지고 첫 항목인 인덱스 252 / 알파 140이 선택됐다. PSD 적용본의 불투명 순백색 3,172픽셀 중 3,151픽셀이 이 항목을 사용했고, 21픽셀만 알파 255였다. 앞선 PNG 검사의 ‘흰색 보존’ 결론은 저장 알파를 확인하지 않아 불충분했다. PSD 디자인이나 얇은 글씨 자체의 문제로 돌릴 수 없다.

## 수정 범위

불투명 입력 픽셀에서 미리보기 RGBA가 동일한 팔레트 후보끼리는 저장 알파가 가장 높은 항목을 선택하도록 했다. 부분 투명 입력과 RGB가 다른 항목은 이 교정에서 변경하지 않는다. 공용 TIM2 해석이나 전체 게임의 알파 범위를 추정해 일괄 변경하지 않았다.

최신 출력: `build/title_alpha_v1/Poison Pink (Japan) - Korean title alpha fix.iso`.

사용자의 PSD에서 디코딩한 PNG를 그대로 사용한다. 기존 PSD 통합 ISO 위에 타이틀 텍스처의 해당 인덱스만 교체한다. 다른 번역·이미지·팔레트·파일 위치는 유지한다. 원본과 이전 ISO를 덮어쓰지 않는다.

## 검증과 한계

- 순백색 3,172픽셀 모두 실제 저장 RGBA (255,255,255,255)를 선택하는지 검사한다.
- 변경된 픽셀은 불투명 입력이며 RGB는 그대로, 저장 알파만 높은 항목으로 이동했는지 검사한다.
- 부분 투명 입력 인덱스, TIM2 헤더·팔레트 보존을 검사한다.
- 전체 ISO를 기준 ISO와 비교하여 계획한 텍스처 외 모든 바이트가 동일한지 확인한다.
- 알파 중복 선택 회귀 검사 2개와 기존 TIM2 코덱 검사 4개를 통과했다.

이전과 수정 후의 클리핑된 미리보기 PNG는 동일하다. 따라서 그 미리보기는 게임에서 투명도가 같다는 증거로 사용할 수 없다. 저장 값의 잘못된 선택은 교정했지만 실제 화면의 최종 결과와 그리기 단계의 투명도 효과는 아직 실행 검증하지 않았다.
