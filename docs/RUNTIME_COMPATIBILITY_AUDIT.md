# 유사 화면·호환 문제 점검 — 2026-09-19

## 수정한 사항

### 1. 다음 ISO에서 PCSX2 보정이 다시 빠지는 문제 방지

기존에는 실행 파일(ELF)의 식별값이 바뀌어도 PCSX2 패치의 대상 식별값은 자동 갱신되지 않았다. `tools/iso_archive_stage.py`의 공통 ISO 출력 단계에 검사를 넣었다.

- 최종 ISO에서 `SYSTEM.CNF`와 `SLPS_258.54`를 직접 읽는다.
- PCSX2의 `ElfObject::GetCRC`와 같은 방식으로 식별값을 계산한다.
- 고정한 원본 ELF·번들 패치 해시를 확인한다.
- 패치 대상 34곳 및 각각 앞뒤 16바이트를 원본과 비교한다. 주변 명령이나 코드 삽입 공간이 다른 경우 빌드를 중단한다.
- ISO가 최종 경로에 나타나기 전에 `<ISO 이름>.pcsx2/`에 그 식별값용 패치·사용 설명·해시 목록을 만든다.
- 패치 충돌이나 보정 패키지 생성 실패 시 ISO를 완성본으로 공개하지 않는다. 사용자 프로필의 패치를 빌드 중 임의로 덮어쓰지는 않는다.

현재 ISO에도 `.iso.pcsx2` 폴더를 생성했다. ISO 본체는 기존 SHA-256 `41021fe51f65c13eb12dbf122f251beaa5a742b287f79f2c2ca05a773bb36b8f` 그대로다. 새 PCSX2 환경에서는 패키지의 `patches` 내용을 PCSX2 데이터 폴더의 `patches`에 설치하고 와이드스크린 패치를 켜야 한다. 이 컴퓨터의 사용자 프로필에는 앞선 수정에서 이미 설치했다.

패치 원문과 검증 기준은 `localization/runtime/`에 보관한다. 패치 작성자는 Arapapa이며 PCSX2 2.6.3 번들에서 가져왔다. 식별값 계산 근거는 [PCSX2 공식 코드](https://github.com/PCSX2/pcsx2/blob/v2.6.3/pcsx2/Elfheader.cpp#L233)다.

### 2. 실제 발견한 테스트 키 충돌 수정

프로젝트 PCSX2의 게임 버튼과 에뮬레이터 단축키가 겹쳤다.

| 게임 버튼 | 입력 | 동시에 실행되던 에뮬레이터 기능 |
| --- | --- | --- |
| △ | F5 | 인터레이스 모드 변경 |
| □ | F6 | 화면 비율 변경 |
| L1 | F9 | Software/Hardware 렌더러 전환 |

프로젝트 프로필에서 해당 에뮬레이터 단축키 3개만 해제했다. 게임 버튼 매핑은 유지했다. 이전 조사에서 문자키 입력이 반응하지 않은 이력이 있어 검증된 기능키를 유지하는 쪽을 택했다.

`runtime_keys.py`는 요청받은 게임 키를 보내기 전에 실제 프로필의 버튼 매핑과 에뮬레이터 단축키 중복을 확인하고, 문제가 있으면 입력을 거부한다. 이전 프로필을 잘못 복원해도 동일 문제가 조용히 재발하지 않게 했다.

사용자의 일반 PCSX2는 △=I, □=J, L1=Q로 중복이 없었다. 사용자 키 설정은 변경하지 않았다.

### 3. 프로필·상태저장 검사 추가

`tools/runtime_compat.py`는 다음을 검사한다.

- 현재 ELF 식별값용 패치가 실제 설정된 패치 폴더에 있는지
- 활성 패치 내용이 검증된 원문과 맞는지
- 와이드스크린·게임 보정 설정이 꺼져 있지 않은지
- 현재 게임별 설정이 전역 설정을 덮어쓰는지, 이전 식별값용 설정이 남아 있는지
- 게임 버튼과 에뮬레이터 단축키 중복
- 상태저장이 다른 ELF용인지, 저장된 보정 34곳이 빠졌는지
- 활성 초상화 대화에서 하단 영역 좌표가 잘못된 `312`로 남았는지

상태저장 검사는 읽기 전용이다. 서로 다른 빌드의 상태저장을 이름만 바꾸거나 일괄 덮어쓰지 않는다. 이번 사용자 프로필에는 현행 슬롯 1만 있었고, 모든 보정값과 대화창 위치 `384`가 정상이다. 원본 백업 `.bak`는 검사·수정 대상에서 제외했다.

## 재현 가능한 확인 명령

프로젝트 루트에서:

```sh
python3 tools/runtime_compat.py \
  --iso 'build/battle_conditions_psd_v1/Poison Pink (Japan) - Korean battle conditions v1.iso' \
  --profile '<LOCAL_USER_HOME>/Library/Application Support/PCSX2' \
  --states '<LOCAL_USER_HOME>/Library/Application Support/PCSX2/sstates' \
  --report reports/runtime_compat_audit.json
```

`--package`를 추가하면 기존 ISO를 변경하지 않고 해당 ISO용 보정 패키지를 만든다. 새 ISO는 공통 빌드 단계에서 자동 생성된다. 검사 실패는 0이 아닌 종료 코드를 반환한다. 실행 전 위 프로필 검사를 통과시킨다.

## 실제 게임 확인과 한계

- 같은 게임의 번들 패치는 1개이며, 현재 보정에는 대화창·마을/전투 캐릭터·저택·상점·휴식소 관련 수정이 함께 들어 있다. 별도로 빠진 이 게임의 번들 패치나 사용자 게임별 설정은 발견하지 못했다.
- 실행 로그에서 게임 데이터베이스의 EE/FPU clamp=0 및 halfPixelOffset=2 적용을 확인했다. 게임의 일련번호가 유지되어 이 보정은 빠지지 않았다.
- 사용자 메모리카드 복제본으로 부팅해 마을, 저택 메뉴, 츠바키히메 관의 거래 메뉴·인물, 마신 도감을 확인했다. 한글 설명·거래 문구의 가림이나 강제 종료는 관찰하지 못했다.
- △로 도감 진입을 확인했다. □·L1 입력 후 화면 설정 변경이나 렌더러 전환 로그는 없었다. 도감 분류 이동 자체는 이번 화면에서 확인되지 않아 별도 통과로 세지 않는다.
- 도감 등의 일본어 이미지 잔존은 번역 범위 문제이며, 이번 호환성 수정으로 번역했다고 주장하지 않는다.
- 후반 전투·모든 상점/휴식소·모든 상태저장을 실행 검증한 것은 아니다. Metal 관련 과거 크래시의 해결을 뜻하지도 않는다. 검증은 Software 렌더러에서 했다.

실행 증거는 `build/runtime_compat_audit/evidence/`, 검사 결과는 `reports/runtime_compat_audit.json`과 `reports/runtime_compat_review.json`에 있다. 테스트 창은 종료했고 프로젝트 설정은 위 단축키 3개만 수정한 원래 구성으로 복구했다. 사용자 창·메모리카드·상태저장은 이번 추가 점검에서 변경하지 않았다.
