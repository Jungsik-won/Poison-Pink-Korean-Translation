# Ratonga RTB 구조와 문자열 길이 변경

2026-09-15. 원본 `SLPS_258.54`의 로더와 opcode 클래스 정보를 근거로 구현했다.
[ELF 원시 명령 증거](RTB_ELF_EVIDENCE.md), [opcode 레지스트리](../localization/rtb_opcodes.json).

## 정적 검증 결과

- RTB **280개, 19,179,720바이트**를 파일 끝까지 파싱하고 필드별 재직렬화 결과가 원본과 일치했다.
- 함수 **23,487개**, 명령 **1,440,116개**, 문자열 리터럴 **126,329개**, 분기 **122,923개**.
- 각 함수의 명령 수가 선언값과 일치한다. 모든 분기의 대상이 같은 함수의 유효 명령 인덱스에 도달한다.
- `t00_0010.rtb`: 함수 120개, 명령 4,574개. 이전 번역 대상은 `_PE0103T` 함수의 명령 인덱스 17, 파일 위치 `0xbb34`다.
- 기존 패턴 후보 37,301개 중 37,278개는 실제 문자열과 일치하고 23개는 오탐이었다. [제외 기록](../localization/rtb_candidate_exclusions.json)에 ID·원문 해시를 남겼다. 새 편집기는 해당 위치의 삽입을 거부한다. 기존 번역 입력은 보존했다.
- 문자열 수에는 ASCII 리소스·디버그·이름·UI 등이 포함된다. 번역 대상 수나 번역률 분모가 아니다.
- **전체 wire 형식과 경계를 읽은 결과**다. 모든 opcode의 연산 의미, packed 비트 의미, 화자·번역 역할을 모두 해석했다는 뜻은 아니다.

기계 판독 결과: [전체 감사](../reports/rtb_structure_audit.json), [튜토리얼 구조](../reports/t00_0010_structure.json).

## 기본 자료형

정수는 little endian이다.

| 형식 | 저장 |
| --- | --- |
| `u8` | 1바이트 |
| `u32` | 4바이트 |
| `count` | 0~253은 1바이트; `fe` 뒤 uint16; `ff` 뒤 uint32 |
| 짧은 문자열 | **u8 길이** 뒤 해당 길이의 원시 바이트; count 형식과 다름 |

초기 `fe`는 RTB 전체의 고정 magic으로 취급하지 않는다. 이 파일에서는 심볼 수 791을 나타내는 count 접두사다.
원본 count가 넓은 형식을 사용했다면 그대로 보존한다. 문자열은 임의로 디코딩/재인코딩하지 않고 원시 바이트를 유지한다.

## 파일 순서

1. 심볼 테이블: count, 반복 `{hash:u32, 이름:짧은 문자열}`.
2. 소스 파일 목록: count, 반복 짧은 문자열.
3. 타입 맵: count, 반복 `{hash:u32, index:u32}`.
4. 타입 기술 목록: count, 반복 `{값:count, hash:u32}`. 첫 값의 세부 의미는 미확정으로 보존한다.
5. export 목록: count, 반복 `{hash:u32, 함수 존재:count, 존재하면 함수}`. 현재 원본 존재 값은 0 또는 1이다. 같은 이름의 오버로드를 합치지 않는다.
6. 모듈 초기화 함수.
7. 전역 슬롯 수 u32. 현재 280개 원본에서 이후 바이트는 없다. 추가 바이트가 있으면 지원하지 않는 입력으로 실패한다.

## 함수 순서

1. 반환 타입 hash:u32.
2. 로컬 맵: count, 반복 `{u32, u32}`.
3. 메타데이터 count 4개. 앞 2개의 정확한 의미는 미확정이다. 뒤 2개는 명령 수와 런타임 명령 객체용 할당 크기다.
4. 명령을 순서대로 읽고 opcode `00`으로 끝낸다. 종료 바이트는 명령 수에 포함하지 않는다.

할당 크기는 디스크에 저장된 문자열 바이트 수가 아니다. 로더는 명령 객체 포인터 배열을 구성하고, 문자열 내용은 문자열 객체에서 별도로 읽는다.
문자열 길이만 변경하는 실험에서는 메타데이터·명령 객체 수·할당 크기를 보존한다.

## 명령 형식

공통 헤더는 `{opcode:u8, packed:u32}`다. 이전 문서의 `mode + debug tag`라는 해석은 확정하지 않는다.
실행 구현에는 packed 값의 레지스터 인덱스로 보이는 비트 사용이 존재한다.

| opcode | 뒤따르는 자료 |
| --- | --- |
| `31`, `32` | 원시 4바이트 정수/부동소수 리터럴 |
| `33` | u8 길이 + 문자열 원시 바이트 |
| `34~3b`, `3d~3f`, `2c` | u32 2개 |
| `67` | count |
| `68~6a`, `29` | u32 2개 + count |
| `2a` | u32 1개 |
| `6b~6d` | signed int32 상대 분기 |
| 나머지 지원 opcode | 공통 헤더만; 정확한 목록은 레지스트리 참고 |

지원 범위는 로더 switch와 RTTI/vtable에서 연결한 `29~6f`다. 알 수 없는 opcode는 검색으로 건너뛰지 않고 실패한다.
명령 중간 문자열 안에 `33 01` 등이 있어도 새 명령으로 인식하지 않는다.

## 분기와 재삽입

`6b`는 jump, `6c`는 jz, `6d`는 jne 클래스와 연결된다.
실행 시 현재 명령 포인터에 `signed_delta * 4`를 더한다. fallthrough는 4를 더한다.
따라서 대상은 **현재 명령 인덱스 + delta**이며, 파일 바이트 오프셋도 다음 명령 기준도 아니다.

문자열만 길이를 바꾸면 디스크 위치는 이동하지만 명령 배열 순서와 분기 값은 그대로다.
편집 도구는 수정 후 다시 파싱해 다음을 검사한다.

- 원본 파일 SHA-256 및 지정 명령의 원문 바이트 일치.
- 수정 대상이 실제 `33` 명령인지 확인; payload 속 패턴은 거부.
- 문자열 최대 255바이트, 잘못된 소스·범위·잘린 입력 거부.
- 모든 함수의 명령 순서·개수·분기 목표·메타데이터 불변.
- 허용한 길이/문자열 필드 이외의 모든 필드 값과 저장 폭 불변.
- 외부 아카이브 HED 크기를 변경하고 기존 파일 시작 위치를 보존. 증가는 확인된 0 패딩 안으로 제한하며 축소로 남는 바이트는 0으로 채움.

DB 형식 및 일반적인 RTB 명령 추가/삭제는 이 편집 도구의 범위 밖이다.

## 도구

```sh
python3 tools/rtb_codec.py
python3 -m unittest discover -s tools -p 'test_rtb_codec.py'
python3 tools/rtb_resize_probe.py longer
python3 tools/rtb_resize_probe.py shorter
```

뒤의 두 빌드는 기존 출력 폴더를 덮어쓰지 않는다. 기존 검증된 32자 폰트, 원본 해시, 검수한 번역 기록을 확인한다.
실험 대사: `전투의 기본을 알려주마.` 23바이트, `전투 기본을 알려주마` 20바이트. 원문은 22바이트다.
